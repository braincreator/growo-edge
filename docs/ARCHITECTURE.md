# Архитектура Growo Edge SDK

Главный принцип: **SDK — адаптер-реле, а не второй экземпляр продукта**.
Мозг (LLM, RAG, скоринг, CRM) всегда живёт в платформе Growo; SDK
переводит между внешним миром (Авито, amoCRM, файлы) и её API.

## Три топологии

### 1. SaaS — всё на платформе (базовая)
```
сайт клиента ──скрипт виджета──┐
amoCRM ←──коннектор+виджет──────┤
Авито/TG/WA ──webhooks──────────┼──► growoai.ru
                               ┘    чат+RAG+LLM+CRM+синка
```
Клиент не деплоит ничего, SDK не нужен.

### 2. Edge-реле — коробка у клиента, мозг у нас
```
Авито ──webhook──► [сервер клиента: docker compose]
                      │ parse → dedup → кастомные правила
                      ▼
                GROWO_API_BASE/api/v1/chat   (X-Tenant-Slug)
                      │ ответ ассистента
                      ▼
                  Avito API ◄── ответ в чат
```
У клиента — стейтлесс-приёмник и `.env` с кредами; история диалогов и
обработка — на платформе. Когда нужна: кастомные правила (расписание,
фильтры), источник во внутренней сети клиента, обязательная передача
исходников по договору.

### 3. Полный on-premise — вся платформа у клиента
Платформа разворачивается у клиента (onprem-kit), LLM — через его ключи
(BYOK). SDK не меняется: `GROWO_API_BASE` указывает на локальную
инсталляцию.

## Что где живёт (матрица покрытия)

| Интеграция | Где живёт | Нужен ли SDK |
|---|---|---|
| Виджет на сайт | платформа (скрипт-тег) | нет |
| amoCRM синк + вход из amo | платформа (коннектор + ZIP-виджет) | нет |
| Telegram / WhatsApp / VK / MAX | платформа нативно | нет |
| Авито-бот простой | платформа нативно | нет |
| Авито-бот с кастомными правилами | edge | да |
| Пуш лидов из любых форм → amoCRM | edge | да |
| Массовая загрузка базы знаний | через API платформы | да |
| Свой канал / системы клиента | edge (клей на заказ) | каркас |
| Telegram/WhatsApp-клиент в SDK | — | нет (нативно; добавим при спросе) |

SDK сознательно не покрывает всё: каналы, живущие в платформе нативно, —
предпочтительный путь (админка, лимиты, биллинг). SDK — для кастомной
логики, инфраструктурной специфики клиента и передаваемых исходников.

## Полный цикл авито-бота (пример)

1. Сообщение в Авито → webhook на приёмник клиента (адрес регистрируется
   `register_avito_webhook.py` однократно).
2. Приёмник: парсинг → дедуп по id (Авито шлёт с ретраями).
3. `GrowoClient.chat(text, visitor_id="avito-{chat_id}",
   session_id="avito-{chat_id}", channel="avito")` → на платформу.
   `session_id` сохраняет контекст переписки.
4. Платформа: embedding (Yandex v2) → гибридный RAG по базе знаний →
   ML-скоринг → LLM-ответ; при квалификации лида — сделка в CRM и автосинк
   в amoCRM (если привязан).
5. Приёмник отправляет ответ через `AvitoClient.send_chat_message`
   (токен обновляется автоматически).

Через клиентскую коробку проходят только текст сообщения и готовый ответ:
никакой бизнес-логики, никаких данных на диске.
